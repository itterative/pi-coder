## Likely regressions / coverage gaps

- **Stale detail title/status:** `AgentSessionDetailComponent.updateItem()` replaces content but not the `PagerComponent` title created from the initial status. A run that completes while detail is open can continue to show `· running` in the header, although the list updates after closing. (`src/tui/agent-session-detail.ts`)
- **Refresh cost while streaming:** every progress event can call `flushPersistence()`, reload the active transcript, and scan/load all past sessions (`src/tools/agent/browser.ts`, `src/tools/agent/presentation/sessions.ts`). The browser coalesces overlapping refreshes, but no test measures long-transcript/many-past-session responsiveness.
- **Integration gap:** the new UI test mocks an event bus and injects transcript strings. It does not exercise the real child session file, persistence flush, formatter, manager progress event, and open-detail refresh together.
- **Follow behavior coverage gap:** no tests cover wrapped/resize-dependent transcript growth, terminal transition while detail is open, or status/title refresh.
- **Documentation mismatch:** `src/tools/agent/README.md` still directs users to `/agent-sessions`, but the implementation registers `/agents`.
