# src/tui component architecture

Shared composable TUI building blocks, extracted to deduplicate dialog and status-footer behavior:

- **`list-view.ts`** — `ListViewComponent<T, R, S>` base class: frame scaffolding (DynamicBorder/title/header/footer/help), configurable `borderColor`, border glyphs, optional header spacing, fixed-height/compact-footer framing, visual-line wrapping, item render cache, cursor-follow scrolling, scroll indicator, ↑/↓/j/k nav, `onKey` hook. Subclass extension points: `getItemPrefix()`, `handleAction()`, `onExternalDone()`, `renderStatus()`, plus compositional `itemPrefix`, `onCacheBuilt`, title, and help updates. Subclasses: `pager.ts`, `select.ts`, and `multi-select.ts`; `SelectComponent` supports opt-in printable-input filtering with a header search indicator via `enableSearch`. The agent browser is now a composed host in `agents/browser.ts`. The unified browser defaults its Agents view to the current parent session, with an `h` toggle for cwd-wide historical sessions, plus Workspaces and Settings views; it opens pager-based read-only session or workspace metadata views.
- **`dialog-queue.ts`** — shared abort-aware FIFO for modal `ctx.ui.custom()` dialogs. `askUser()` and `selectWithMessage()` both use it; future permission dialogs must use one of these queued entrypoints rather than calling `ctx.ui.custom()` directly. Queued cancellation returns promptly without allowing later dialogs to overtake the active one.
- **`confirmation.ts`** — reusable `ConfirmationComponent` and `confirm()` helper for centered, focus-safe yes/no overlays. The helper participates in `withOverlayStack`, so it can be opened from an existing overlay; the delegated-agent browser uses it for agent cancellation and workspace disposition actions.
- **`inline-editor.ts`** — `InlineEditor`: theme-free inline edit engine (segment buffer with atomic paste placeholders, bracketed paste, pi-tui-matching word movement/deletion, display↔content mapping, windowed `renderLines()` returning plain strings). Composed by `ask-user.ts`, `select-with-message.ts`, and `numeric-input.ts`; callers supply styling via pre-styled prefixes/placeholders and set `editor.focused`.
- **`text-input.ts`** — `TextInputComponent<T>`: the generic modal inline field (`InlineEditor` + `BorderBox`)
  with caller-supplied `parse`/`format`, an optional `fieldLabel`, and validation errors; `textInput()` opens it
  through `withOverlayStack`. `numeric-input.ts` is now a facade over it — `NumericInputComponent` is an alias,
  `numericInput()` forwards with the numeric placeholder, and `parsePositiveInteger` stays.
- **`decision/`** — Decision-model settings package (`settings.ts` + index): a `ListViewComponent` subclass with
toggle/field rows, opening a searchable classifier `SelectComponent` and `textInput` s as nested overlays. The
agent browser Settings tab opens it through `onDecisionModelOpen`. The folder mirrors `agents/` as the place for
decision-specific TUI, not the status package.
- **`numeric-input.ts`** — numeric facade over `TextInputComponent`; use `numericInput()` for settings that need
arbitrary numeric values instead of fixed choice lists.
- **`spinner.ts`** — `Spinner`: small reusable animated frame component with configurable frames/interval, `setActive()`, and `dispose()`. It requests TUI renders while active, pauses on the shared `pi-coder:tui-dialog` EventBus event, and is used by the delegated-agent status footer.
- **`agents/`** — Agent-specific browser TUI package. Its browser, session/workspace details, and workspace browser implement `Component` and compose the generic list/pager/select components. Agent browser imports should use this package directly. Session-transcript projections, including TODO transcript formatting, belong under `src/tools/agent/presentation/` rather than the status package.
- **`status/`** — Shared parent status footer. `footer.ts` registers one custom footer through `ctx.ui.setFooter()` for the whole session (session start/tree re-register it; shutdown restores the built-in footer) and renders exactly one compact line. The left cluster is the agent summary (`formatAgentSummary` in `agent-activity-format.ts` — waiting runs first, then running, then terminal; one run's label plus detail, with `+N` for extra visible/hidden runs), TODO progress (`formatTodoProgress` in `format.ts`, current item capped in the footer for one-line use), and `setStatus` extension statuses. The right-aligned cluster is usage totals (`120k tok · $0.133 · CH42.9%`, cost only when nonzero and cache hit only when the session reported cached tokens), context utilization, the model, and the cwd/branch repo — rightmost. Built by `footerInfoSegments` from `footer-info.ts`; totals are cached per session/leaf/entry count by `UsageTotalsCache` (features-detects `getEntryCount` to avoid copying the session each frame). The right cluster reserves its width first, so `layoutFooterLine`'s `FooterLineSegment[]` prunes the left first: extension statuses → TODO → agent, down to one segment which is then truncated; right segments shed only when the right cluster alone cannot fit (model → usage → repo → context last). It replaced the old above-editor `setWidget` registration and the itemized multi-line renderers; pi's working spinner stays in the editor border. Domain modules publish typed `pi.events` snapshots on `pi-coder:status-agent` and `pi-coder:status-todo`, while the status package alone owns footer registration, the `Spinner`, and event listeners; `invalidate()` is a no-op because each render rebuilds the line from pushed state.
- `ListViewComponent` fits fixed-height frames by reserving space for scroll indicators/wrapped footers and placing a flexible spacer before help text, so compact agent detail/workspace views anchor help at the bottom; it restores the configured viewport size when dimensions change. It caches rendered and wrapped item lines across scroll-only renders; `invalidate()` marks that cache dirty for content changes, while custom key handlers use the non-cache-invalidating path for offset-only navigation.
- `AgentSessionDetailComponent` clamps its pager scroll offset after transcript content changes, which is required when switching from a long detailed transcript to a shorter collapsed one. When an open live run transitions to a historical row without preloaded transcript text, the browser must trigger the lazy transcript loader again before the detail can retain the final transcript/TODO projection. When a lazy transcript resolves, update the open detail before invalidating cached browser state, then call the host `onInvalidate` callback so the TUI redraws without waiting for another keypress.
- Agent transcript formatting collects ordered conversation entries separately from one optional TODO entry. The renderer inserts that TODO immediately after the initial user context (or at the start when no user entry exists), then applies detailed or collapsed tool-call rendering. The session detail overlay receives structured transcript parts, renders prose through Markdown, and emits tool-call parts as plain lines. Detailed edit/write calls default to concise changed-line counts; the formatter retains an opt-in constant for full diff lines if that presentation is desired later. Presentation tests cover ordering and browser snapshots cover the resulting TUI.

Tests: `test/` (vitest). `test/inline-editor.test.ts` unit-tests the editor engine; `test/helpers.ts` provides the headless harness for component rendering tests (`mockTheme` identity theme, `KEY` raw key map, `press`/`type`/`paste`, `interact()` which renders after every keypress like the real TUI loop — needed because InlineEditor up/down reads render-computed visual-line state, and `renderText()` which strips CURSOR_MARKER and renders inverse-video cursor chars as `[X]`). TUI rendering tests use file snapshots. Agent UI imports use the composed `src/tui/agents` package; add focused package tests when extending its controller/lifecycle behavior. When changing edit behavior, change InlineEditor once — both dialogs inherit it.
