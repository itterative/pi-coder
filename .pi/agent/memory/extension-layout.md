---
name: extension-layout
description: pi-coder is the consolidated extension; memory, agent, and sandbox modules are registered from src/index.ts.
category: architecture
---

The consolidated extension entrypoint is `src/index.ts`. It registers the memory and reminders modules, the temporary scratchpad module, the shared compaction override (`src/modules/compaction`, which replaces pi's own summarization for the parent and every child), config command (`src/commands/config.ts`), the `/stats` usage command (`src/commands/stats`, see `stats-command.md`), in-process agent tool, ask-user tool, bash hook, and read/write file-tool hooks; the audit command is intentionally not migrated. Agent implementation lives under `src/tools/agent` with tests under `test/tools/agent*.test.ts`; its `index.ts` registration function composes top-level `lifecycle.ts`, `browser.ts`, and `action-dispatch.ts` modules. Agent TUI is packaged under `src/tui/agents`, where agent-specific components compose the generic list/pager/select primitives. Agent lifecycle events use pi's namespaced `pi-coder:agent-event` event bus channel, with event contracts in `src/tools/agent/contracts/events.ts` and the event-bus adapter in `src/tools/agent/observability/events.ts`. Sandbox implementation lives under `src/modules/sandbox`, shared file-tool guarding under `src/tools/file-permissions.ts`, memory under `src/modules/memory`, and reminders under `src/modules/reminders`, with tests under `test/modules` and config tests under `test/common`.

**Runtime state lives outside the checkout.** `PI_CODER_STATE_DIR` (default `<agent-dir>/pi-coder`, i.e. `~/.pi/agent/pi-coder`; `PI_CODER_STATE_DIR` overrides it) holds `agent-sessions/`, `workspaces/`, `meta.sqlite`, `bash-log.jsonl*`, `compaction-trace.jsonl*`, `container/`, and `perf/`. It must never sit inside the extension checkout: pi updates a git-installed package with `git reset --hard` followed by `git clean -fdx`, and `-x` deletes ignored files too, so anything under `<checkout>/.state/` is destroyed by the next update. That root is also a sandbox read-only resource root (`standardAgentResourceRoots`), which is how the report scripts and session-review keep reading it. Memories that quote `<checkout>/.state/...` paths describe the layout before the 2026-11 relocation; the file names are unchanged, only the root moved.

**A development checkout pins its own environment in `<checkout>/.env`** (gitignored, documented by `.env.example`; loaded by `src/common/dev-env.ts` from the extension root only, never the caller's cwd). Only pi-coder's own prefixes apply (`PI_CODER_`, `PI_SANDBOX_`, `PI_MEMORY_`, `SANDBOX_`, `COMPACTION_`, `DECISION_MODEL_`, `AGENT_CONFIG_`); an explicitly set env var wins; `PI_CODER_ENV_FILE=0` disables the file, and any other value names an alternate one. A relative `PI_CODER_STATE_DIR` resolves against the extension checkout. This is how the dev tree keeps using `<checkout>/.state` (so branch switches keep the same state) while a git-installed copy, which has no `.env`, uses `<agent-dir>/pi-coder`. `test/setup.ts` pins `PI_CODER_ENV_FILE=0` so a developer's file cannot change what a suite asserts.
